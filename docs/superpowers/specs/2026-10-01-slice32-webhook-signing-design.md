# Slice 32 design: signing the alert webhook

## Context

Codebase facts: main `5ec4c1d`, checked 2026-10-01.

The third of the four smaller items the user ordered on 2026-10-01 (labels, rate limits, webhook signing, "-es" folding). docs/findings-slice13.md records the gap: "No webhook signing; a consumer cannot authenticate the sender." The slice 13 spec's cost line says "add an HMAC header later."

Facts read before the approaches (direct reads on Fable 5.1):
- Delivery is `deliver_due_alerts` in apps/workers/bsi_workers/worker.py: a `tenant_session` read of the alert and brand assigns `url, body = (brand.webhook_url, json.dumps(payload(alert, brand.name), default=str).encode())`, the session closes, then `fetch(url, WEBHOOK_UA, method="POST", body=body, content_type="application/json")`. The `Poster` protocol fixes that call signature. Retries follow `BACKOFF_DELIVERY`; the webhook-cleared check uses `SELECT … FOR UPDATE` on `brand.webhook_url`.
- `http_fetch` in packages/core/bsi_core/crawl.py builds its headers dict inline (`Host`, `User-Agent`, `Accept-Encoding`, and `Content-Type` when given). There is no parameter for other headers. It is shared with crawling, feeds and sitemaps, so any change to it is covered by tests/unit/test_http_fetch.py.
- `Brand.webhook_url` (packages/core/bsi_core/models.py, migration 0016) is validated by `_webhook_url` in apps/api/bsi_api/routers/brands.py: HTTPS, public host, default port, no userinfo. So a header carrying a signature is never sent in clear.
- `BrandOut` (`from_attributes=True`) returns `webhook_url`; `_patch` applies every set field of `BrandPatch` with `setattr`; `patch_brand` nulls pending deliveries when `webhook_url` is set to null. Migrations end at 0021. `Organization.settings` (JSONB, default `{}`) is unused.
- The web form is apps/web/src/app/(app)/b/[id]/alerts/page.tsx with the server action `setWebhook` in actions.ts (`clear=1` or an empty URL sends `webhook_url: null`); notes are in `ALERT_NOTES` in apps/web/src/lib/format.ts; `Brand` is `S["BrandOut"]` from the generated schema.
- Tests: tests/unit/test_alerts.py (`payload`), tests/unit/test_http_fetch.py (the recording `MockTransport` and `test_post_sends_the_body_and_content_type_to_the_pinned_address`), tests/integration/test_worker.py (`_Hook` fake poster; six delivery tests from line 930, of which only `test_deliver_posts_the_payload_and_marks_delivered` unpacks `_Hook`'s tuple, and three — `test_no_transaction_is_open_during_the_webhook_post`, `test_one_failing_delivery_does_not_block_the_rest`, `test_a_delivery_that_fails_after_the_webhook_is_cleared_is_given_up` — define a local `fetch(url, ua, *, method, body, content_type)` instead of `_Hook`), tests/integration/test_api_alerts.py (webhook URL validation, clearing). tests/integration/test_isolation.py already has `("PATCH", "/v1/brands/{b}", {"name": "x"})`.

Classification, said in chat as the first line of the first brainstorming reply: **architectural** — "webhook signing adds a new interface (a signature header that receivers verify), a stored secret (new column or JSONB key, possibly migration 0022), a change to the shared `crawl.http_fetch` (which crawling also uses), plus API, web and worker changes."

Decisions approved in chat (brainstorming on Fable 5.1, 2026-10-01, in plan mode; implementer and reviewer subagents on Opus 5.5). Each decision had three approaches with trade-offs and a recommendation in a chat message before its question:
- D1, where the secret lives: a per-brand column `brand.webhook_secret` (over a per-org key in `Organization.settings`, and a global env secret). The user chose the per-brand column.
- D2, how the operator sets it: the operator supplies it, write-only on `PATCH /v1/brands/{id}`, and `BrandOut` reports only `has_webhook_secret` (over a server-generated secret shown once by a new route, and auto-generation on the first URL set). The user chose operator-supplied.
- D3, the format: one header, `X-BSI-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256>` over `"{t}." + body` (over a plain body HMAC with no timestamp, and the Standard Webhooks three-header spec). The user chose the timestamped HMAC.
Each design section's text was in chat before its approval question; the user approved Sections 1–5, and with Section 5 the API-only live check. The user then approved the plan-mode plan.

## Design

### 1. Data and API

- Migration `migrations/versions/0022_brand_webhook_secret.py` (`revision = "0022"`, `down_revision = "0021"`): `op.add_column("brand", sa.Column("webhook_secret", sa.Text()))`; downgrade drops it. Nullable, no default, no index. No new table, so no RLS, `TENANT_TABLES`, `org_b` or isolation `CASES` work.
- `models.Brand.webhook_secret: Mapped[str | None]` under `webhook_url`, with the comment: shared with the receiver, read only by the worker when it signs a delivery; null = unsigned. A property `has_webhook_secret` on `Brand` returns `self.webhook_secret is not None`, so `BrandOut` (`from_attributes=True`) can read it without a validator.
- In apps/api/bsi_api/routers/brands.py: a type `WebhookSecret = Annotated[str, Field(min_length=32, max_length=200), AfterValidator(_webhook_secret)]` where `_webhook_secret` raises `ValueError("no surrounding whitespace")` when `value.strip() != value` (the receiver's copy must match byte for byte). `BrandPatch.webhook_secret: WebhookSecret | None = None`. `BrandOut.has_webhook_secret: bool`. `BrandOut` does not list `webhook_secret`, so no route returns it.
- `patch_brand`: `_patch` already applies `webhook_secret` (set or null) through `setattr`. In the existing `webhook_url is None` branch, also `brand.webhook_secret = None`: a secret without a URL is dead state. Setting a secret with no URL is allowed; it waits. The pending-delivery nulling is unchanged.
- `npm run gen` afterwards; `apps/web/openapi.json` and `apps/web/src/lib/schema.d.ts` are committed.

### 2. Signing and delivery

- In packages/core/bsi_core/alerts.py, after `payload`:

```python
def sign(secret: str, body: bytes, now: int) -> str:
    """The X-BSI-Signature value: `t=<now>,v1=<hex>` where the digest is
    HMAC-SHA256 with `secret` over `"{now}." + body`. The receiver
    recomputes it from the raw body and rejects a stale `t`."""
    mac = hmac.new(secret.encode(), f"{now}.".encode() + body, hashlib.sha256)
    return f"t={now},v1={mac.hexdigest()}"
```

  `hmac` and `hashlib` are stdlib; `now` is a parameter so the unit test is deterministic (the worker passes `int(time.time())`).
- `crawl.http_fetch` gains a keyword `headers: Mapping[str, str] | None = None` (import `Mapping` from `collections.abc`, where `Callable` already comes from). The loop's local dict, today also named `headers`, is renamed `sent` (R3: with one name, on a GET redirect the second hop would merge the first hop's dict instead of the caller's). Each hop sends `sent = {k: v for k, v in (headers or {}).items() if k.lower() not in _PINNED} | {"Host": host, "User-Agent": user_agent, "Accept-Encoding": "gzip, deflate"}` with `_PINNED = frozenset({"host", "user-agent", "accept-encoding"})` a module constant, plus `Content-Type` when given. The caller's keys are dropped by lower-cased name, so a caller cannot override or duplicate the Host the SSRF guard checked, the User-Agent or the Accept-Encoding in any letter case (httpx would otherwise send both `host` and `Host`). `Content-Type` is not in `_PINNED`: a caller key `content-type` beside the `content_type` argument would be sent twice; the only caller passes `X-BSI-Signature` alone. Caller headers go on every hop, including a GET redirect's target. Nothing else in `http_fetch` changes (resolution, pinning, redirects, decoding, cap, timeouts). The docstring gains one line: "`headers` go on every hop; Host, User-Agent and Accept-Encoding are always the pinned ones."
- `worker.Poster.__call__` gains `headers: Mapping[str, str] | None = None` (worker.py imports `Mapping` beside `Callable` from `collections.abc`, and `sign` beside `payload` from `bsi_core.alerts`). In `deliver_due_alerts`, the existing tenant-session read also takes `brand.webhook_secret`; after the session closes, `headers = {"X-BSI-Signature": sign(secret, body, int(time.time()))} if secret else None` and the call becomes `fetch(url, WEBHOOK_UA, method="POST", body=body, content_type="application/json", headers=headers)`. The POST still runs with no transaction open; the attempt count, backoff and the `FOR UPDATE` cleared-check are unchanged. A brand with a URL and no secret is delivered exactly as today (no header), so existing receivers such as Slack incoming webhooks see no change.
- Receiver contract (in the page help text and findings): compute HMAC-SHA256 with the shared secret over `"{t}." + raw body`, compare to `v1` in constant time, and reject when `|now − t| > 300` seconds. The signature is over the exact bytes sent, so the receiver must verify before parsing or re-serialising the JSON.

### 3. Web

- apps/web/src/app/(app)/b/[id]/alerts/page.tsx: the URL input gains `required` (R1), so "Save webhook" is blocked by the browser when the URL field is empty; "Clear" keeps `formNoValidate`. The form gains a second input, `name="webhook_secret"`, `type="password"`, `minLength={32}`, `maxLength={200}`, `autoComplete="off"`, placeholder "Signing secret (optional, 32+ characters)", no `defaultValue` (the API never returns it). Beside it a muted span from `brand.has_webhook_secret`: "Signing on" or "Unsigned". When `has_webhook_secret` is true, a third button `name="clear_secret" value="1" formNoValidate` labelled "Remove secret". A secret saved with no URL ("it waits", §1) is therefore reachable only through the API. The help paragraph gains: "With a signing secret set, each POST carries `X-BSI-Signature: t=<unix seconds>,v1=<hex>`, an HMAC-SHA256 with the secret over `t`, a dot, and the raw body; reject a `t` more than 5 minutes old."
- actions.ts `setWebhook`: reads `webhook_secret` as typed, not trimmed (R4: the API's whitespace rule returns 422 for a padded paste, which is the guard; trimming would silently save a different secret), and `clear_secret`. Body: `webhook_url` as today; plus `webhook_secret: null` when `clear_secret === "1"` (Remove secret wins over a filled field), `webhook_secret: value` when the field is non-empty, and no key when it is empty (the secret is left as it is). The redirect's `queued=` value is `secret_removed` whenever `clear_secret` was pressed (with any URL field), else `cleared`/`saved` as today. The URL "Clear" button is unchanged; the API nulls the secret with the URL.
- apps/web/src/lib/format.ts: the `ALERT_NOTES` literal gains the key `secret_removed: "Signing secret removed; deliveries are unsigned."`, and `cleared` becomes "Webhook cleared; any signing secret was removed." (R4). apps/web/src/lib/format.test.ts's `alertNote` test gets the new `cleared` text and one `secret_removed` line.
- `Brand` picks up `has_webhook_secret` from the regenerated schema. No other vitest change: `setWebhook` is a thin fetch wrapper, as `scanNow` is, and neither has a test today; `npm run gate` keeps the 43 tests green.

### 4. Tests

- tests/unit/test_alerts.py: `test_sign_is_an_hmac_over_t_dot_body` — with `now = 1700000000`, `secret = "s" * 32` and `body = b'{"text":"hi"}'`, `sign()` equals `f"t=1700000000,v1={hmac.new(b"s" * 32, b"1700000000." + body, hashlib.sha256).hexdigest()}"`; appending a byte to the body changes the result.
- tests/unit/test_http_fetch.py, after `test_post_sends_the_body_and_content_type_to_the_pinned_address`: `test_extra_headers_are_sent_but_cannot_override_the_pinned_ones` — a POST through `server(ok)` with `headers={"X-BSI-Signature": "sig", "Host": "evil.example", "user-agent": "spoof", "ACCEPT-ENCODING": "br"}`; the recorded request's raw headers, names lower-cased (httpx keeps the sent letter case in `headers.raw`), hold exactly one `host` ("hook.example.com"), one `user-agent` ("UA") and one `accept-encoding` ("gzip, deflate"), and `x-bsi-signature` is "sig".
- tests/integration/test_worker.py: `_Hook.__call__` gains `headers=None` and records `(url, ua, method, content_type, json.loads(body), body, headers)`; the one tuple unpacking, in `test_deliver_posts_the_payload_and_marks_delivered`, is widened and that test also asserts the recorded `headers is None`. The three local `fetch` fakes named in Context gain `headers=None` too (R2); without it the worker's `headers=` keyword raises `TypeError` inside `deliver_due_alerts`, which swallows it, and those three tests fail. New `test_deliver_signs_when_the_brand_has_a_secret`: `_hooked_brand` plus `webhook_secret = "s" * 32` set through the owner session; after `deliver_due_alerts(fetch=hook) == 1`, parse the header as `t=<int>,v1=<hex>`, assert `abs(time.time() - t) < 60`, and assert `v1` equals the HMAC recomputed from the secret and the recorded raw bytes.
- tests/integration/test_api_alerts.py: `test_secret_is_write_only_and_shown_as_a_flag` — PATCH `{"webhook_secret": "s" * 32}` → 200, the body has no `webhook_secret` key and `has_webhook_secret` is true, the owner session reads the secret back; `test_a_short_or_padded_secret_is_rejected`, parametrized over `"s" * 31` and `" " + "s" * 32` → 422; `test_clearing_the_url_also_clears_the_secret` — set both, PATCH `{"webhook_url": null}` → `has_webhook_secret` false and the column null; `test_null_clears_only_the_secret` — set both, PATCH `{"webhook_secret": null}` → `has_webhook_secret` false and `webhook_url` unchanged.
- No new RLS or isolation rows (no new table or route). Migration 0022 runs under `conftest`'s `alembic upgrade head` on `bsi_test`.
- Red and green, checked on 2026-10-01 on scratch copies outside the repo (a patched copy of `bsi_core` and a test file in a separate folder): on main's code the two unit tests fail at collection (`ImportError: cannot import name 'sign' from 'bsi_core.alerts'`); with the patched copy `2 passed`; `mypy --strict` with the repo config is clean on the two patched modules. The integration and API tests are written in execution and run against the shared test DB.
- Copy: new strings, test names, fixtures and comments are checked against `FORBIDDEN` in tests/unit/test_recommend_copy.py by a grep of the diff.

## Rulings

- **R1: the URL input is `required`.** Decided: the alerts page's URL input gains `required`, so "Save webhook" is browser-blocked with an empty URL field; "Clear" and "Remove secret" keep `formNoValidate`; the API is unchanged, so a secret saved with no URL is reachable only through the API; the user chose this over omitting `webhook_url` from the body when the field is empty, or keeping today's behaviour and documenting it. Found by the spec review of cd76bde (the form always sends `webhook_url`, null when empty, so a secret typed with an empty URL would be nulled by `patch_brand` and the note would say "Webhook cleared."). Why: the dropped-secret case cannot happen from the page, with no change to the API or to "empty URL means clear". Cost if wrong: an operator cannot save a waiting secret from the page. Asked in chat.
- **R2: the three local `fetch` fakes and `_Hook` all gain `headers=None`.** Decided: in tests/integration/test_worker.py, `_Hook.__call__` and the local `fetch` in `test_no_transaction_is_open_during_the_webhook_post`, `test_one_failing_delivery_does_not_block_the_rest` and `test_a_delivery_that_fails_after_the_webhook_is_cleared_is_given_up` accept `headers=None`; the spec says six delivery tests, one of which unpacks `_Hook`'s tuple. Found by the spec review of cd76bde (the spec said five tests and "the existing tuple unpacking in the five delivery tests is widened"). Why: the worker always passes `headers=`, and `deliver_due_alerts` swallows the resulting `TypeError`, so those three tests would fail silently on the count. Cost if wrong: none. Named in chat when made.
- **R3: `http_fetch` renames its local to `sent` and drops the pinned names case-insensitively.** Decided: the parameter is `headers`; the loop's local dict is `sent`; caller keys whose lower-cased name is in `_PINNED` (`host`, `user-agent`, `accept-encoding`) are dropped before the pinned headers are merged; caller headers go on every hop; the unit test spoofs with mixed-case keys and asserts one raw header per pinned name. Found by the spec review of cd76bde (with one name a GET redirect would merge the first hop's dict; a case-sensitive merge lets `host` ride beside `Host`, and httpx sends both). Why: the approved property "a caller cannot override the pinned headers" must hold in any letter case, and the shared function must stay mypy-clean. Cost if wrong: a few more lines in a shared function, covered by the new test. Named in chat when made.
- **R4: the web action does not trim the secret; Remove secret wins; the `cleared` note mentions the secret.** Decided: `setWebhook` sends the secret as typed (the API's whitespace rule, 422, is the guard); `clear_secret` wins over a filled secret field; the `queued=` value is `secret_removed` whenever Remove secret was pressed; `ALERT_NOTES.cleared` becomes "Webhook cleared; any signing secret was removed." and format.test.ts follows. Found by the spec review of cd76bde (§3's trimming contradicted §1's byte-for-byte rule; precedence and the silent secret removal on Clear were unstated). Why: one rule for whitespace, stated precedence, and no silent removal. Cost if wrong: copy only. Named in chat when made.
- **R5: the review's remaining minors were applied.** Decided: worker.py's `Mapping` and `sign` imports named; the live check's brand id written in full; the `ALERT_NOTES` change worded as a new key in the literal and the redirect parameter named `queued=`; format.test.ts's `alertNote` test named; Context's description of the body assignment matches the code. Found by the spec review of cd76bde. Why: accuracy for the plan writer. Cost if wrong: none. Named in chat when made.
- **R6: the re-review's three minors were applied.** Decided: the claim that `mypy --strict` rejects the indexed assignment is dropped from §2 and R3 (the rename stands on the redirect-hop reason; the review ran mypy on that shape and it passes); §4 says raw header names are compared lower-cased, since httpx keeps the sent case; §2 says `Content-Type` is not in `_PINNED`. Found by the re-review of 6a9bd3f. Why: the spec must state no false fact. Cost if wrong: none. Named in chat when made.

## Out of scope

- The last ordered item ("-es" folding): slice 33.
- Server-generated or rotated secrets, a secret per webhook rather than per brand, a signature over anything but the raw body, `X-RateLimit`-style headers, a delivery log, re-delivery of alerts created before a webhook was set, and Standard Webhooks compatibility.
