# Slice 33 findings: folding "-es" plurals in `rivals._stem`

## 1. What was built

The open item "`-es` plurals (dresses, watches, boxes) do not fold with `_stem`" (docs/findings-slice19.md §3, and the one-sided fix in docs/findings-slice21.md §3) is closed: `rivals._stem` now folds `-es` plurals after ch, sh, x, ss and zz, and keeps words ending in "ss" whole. It was the last of the four smaller items the user ordered on 2026-10-01.

Spec: docs/superpowers/specs/2026-10-01-slice33-es-folding-design.md (rulings R1–R10). Plan: docs/superpowers/plans/2026-10-01-slice33-es-folding.md (Tasks 1–2). Merged via PR #63 (main `47ee35f`).

**Code**:
- packages/core/bsi_core/rivals.py: `_ES = ("ches", "shes", "xes", "sses", "zzes")` and the new `_stem(word)`: on a word longer than four characters ending in one of `_ES`, drop the last two characters (watches → watch, dishes → dish, boxes → box, dresses → dress, glasses → glass); else keep a word ending in "ss" whole (glass stays glass; the old rule gave "glas"); else drop one trailing "s" on words longer than three characters, as before (shoes → shoe, kids → kid, mens → men).
- packages/core/bsi_core/products.py: two docstrings only (`fold`, `_allowed_stems`). `_allowed_stems` keeps its one-sided `-es` set (R1): an allowed "contact lenses", "baby clothes" or "potatoes" still backs a suggested "Lens", "Cloth" or "Potato", which the new `_stem` does not fold.
- Every `_stem` caller picks the rule up: 15 direct calls in products.py (`fold`, behind `fold_set` and through it `rule_check`'s title folding and repeat removal; `keyword_key`; `missing` and `dropped`; `title_first`; `_allowed_stems`; the noise, audience and brand stems) and one in rivals.py (`_words`, behind `slug_words` and `topic_words`, which recommend.py matches against content-gap topics). Both sides of every comparison go through `_stem`, and no stem is stored in the database.

**Effects**:
- Folds that now happen: "Dress Dresses" in a rewrite is a repeat and is removed (the slice 19 echo); "Watches" in a title counts as "watch" for missing words; `keyword_key("men watches") == keyword_key("men watch") == "men watch"`; a rival slug "kids-watches" matches the topic "kids watch".
- Accepted limits (R2; the test pins `caches`, `mousses` and `quizzes`): a word whose singular ends in `-che`, `-sse` or `-xe` no longer meets its singular, though the old one-`s` rule folded those pairs (`caches → cach`, `niches → nich`, `quiches → quich`, `headaches → headach`, `mousses → mouss`, `lacrosses → lacross`, `posses → poss`, `pickaxes → pickax`); `quizzes → quizz` never meets `quiz`. An allowed plural of that shape no longer backs its singular either (an allowed "hair mousses" with a suggested "Mousse": `pass` before, `adjusted` after). `-ies` and `-oes` are untouched (`accessories → accessorie`, `potatoes → potatoe`, as before).
- Cached keyword searches (spec §1 with the R9 correction and the R10 note): the run's `key_map` maps each cached `keyword_search` row by its stored spelling through the new `keyword_key`, and the cache lookup is by spelling, so a cached row keeps serving its own spelling. A singular and a plural spelling that now share one key ("men watch" and "men watches", "glass" and "glasses") can share one search, so fewer searches; a keyword that pairs with a cached `-che`, `-sse` or `-xe` singular (a cached "hair mousse" and a new "hair mousses") no longer shares its key, so one more grounded search (about 38,000 micros). Dev's 10 products and 9 cached keywords contain no affected word: a read-only check after merge found that none of their 71 distinct tokens changes stem under the new rule (the ledger's "Dev product read" line).

**Tests**:
- tests/unit/test_rivals.py: `test_stem_folds_plurals` replaces `test_stem_drops_one_trailing_s_on_longer_words`: `sneakers → sneaker, shoes → shoe, kids → kid, bus → bus, glass → glass, watches → watch, dishes → dish, boxes → box, dresses → dress, glasses → glass, quizzes → quizz, sizes → size, caches → cach, mousses → mouss`.
